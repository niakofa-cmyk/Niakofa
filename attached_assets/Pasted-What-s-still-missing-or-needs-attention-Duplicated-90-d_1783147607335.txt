What's still missing or needs attention
Duplicated 90-day auto-default logic with inconsistent behavior — a real bug. Both pledge-worker.ts and scheduler.ts independently implement pledge auto-default after 90 days [niakofa-cmyk/Niakofa/attached_assets/Pasted--The-gap-and-it-s-a-significant-one-Pay-it-forward-and-_1783088650350.txt]. Both use an idempotent WHERE pledge_status='active' guard, so they can't double-penalize the same row — but whichever one wins the race produces a different outcome: scheduler.ts's version applies a trust-score AND goodwill-score penalty; pledge-worker.ts's version only sends an email/push notification with no trust penalty at all. A requester's actual penalty depends on which cron happens to fire first — that's non-deterministic behavior that should be consolidated into one worker.
No dedup on recurring reminders. Both processScheduledReminders (scheduler.ts, every 6h) and the pledge-worker's overdue-scheduled-payment loop (daily) will re-send the same reminder indefinitely for as long as a scheduled payment sits unpaid — no "already reminded" tracking. Low severity, but could feel spammy to users who intend to pay later.
No reinstatement path after default. Once pledge_status flips to defaulted, the only path back is a manual admin action (per code comments) — there's no self-service partial-repayment-to-reinstate flow, which cuts against the "no pressure, pay whenever you can" spirit of the vision.
/analyze-image — status unconfirmed this session. Prior audits flagged this as an orphaned endpoint (built, never called from the frontend). Repeated code searches this session returned zero hits for it in the current tree, which is inconclusive rather than a confirmed fix — worth a direct check next session if photo-based request creation ("snap what needs fixing") is still on your roadmap.
No direct confirmation of the Stripe-side balance backing the pool. The ledger (communityPoolLedgerTable) is pure accounting — nothing in the code confirms the pool actually holds real Stripe balance to fund its transfers. Worth a live test transfer before scaling volume.
