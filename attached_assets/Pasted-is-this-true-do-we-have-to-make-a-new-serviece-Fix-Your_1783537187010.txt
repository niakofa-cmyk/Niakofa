That's exactly why the app can't connect properly and migrations fail with extension "postgis" is not available.
Your Current Setup

* Image: ghcr.io/railwayapp-templates/postgres-ssl:18 → Standard Postgres (no PostGIS extension).
* Internal URL: postgres.railway.internal:5432 (good for private networking).
* The app (api-server + Nia) expects PostGIS for location data.
Step-by-Step Fix

1. Delete the Current Postgres Service
   * Go to your Postgres service → Settings → Delete Service (bottom).
   * Warning: This removes the service. If you have important data, first create a backup via the Backups tab or export via psql.
2. Create a New PostGIS Postgres Service
   * In Railway, click New Service → Database → Search for "PostGIS".
   * Or use custom image: postgis/postgis:16-3.4 (or latest postgis/postgis).
   * Name it something like niakofa-postgis.
   * Enable Private Networking so it gets postgres.railway.internal.
   * Attach any existing volume if you want to preserve data (may need manual restore).
3. Update Environment Variables
   * In your api-server service (zesty-ambition):
      * Update DATABASE_URL to the new Postgres internal URL (copy from new service → Variables).
   * Do the same for Nia service if it has its own DB connection.
4. Redeploy Everything
   * Redeploy api-server (Railway will run migrations automatically via railpack.json).
   * Redeploy Nia service.
   * Run seed scripts manually if needed:
Bash

```
pnpm --filter @workspace/scripts run seed-if-empty
pnpm --filter @workspace/scripts run seed-test-accounts
```

5. Verify
   * Check Deploy Logs for successful CREATE EXTENSION postgis.
   * Test connection: curl health endpoint or load the app.
