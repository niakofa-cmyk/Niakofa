I also enhanced RTC in V23

There was a subtle architectural gap:

Previously the call component was mounted only for the currently selected Direct conversation.

That meant an incoming call could potentially arrive while the user was looking at another Messages thread.

V23 changes that.

The call listener now remains mounted at the Messages-workspace level and can resolve:

Incoming call
      ↓

      ↓
caller ID
      ↓
caller profile
      ↓

So an incoming Direct call isn't dependent on the user already having that conversation open.

I also added a Start audio fallback for browsers/mobile environments where autoplay is blocked. LiveKit documents that browser audio playback may require explicit user interaction and provides Room.startAudio() for that case.

That is particularly important for real iOS/Android testing.
