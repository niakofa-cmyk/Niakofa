One real thing to fix now: the z-index comments are backwards
BottomSheet.tsx, BestMatchCard.tsx, and MapControlsPanel.tsx all have comments describing the stacking order, and they don't match the actual code:

Comments say BottomSheet is z-30 and BestMatchCard is z-20.
The actual values are the reverse: BottomSheet.tsx line 97 is z-20, BestMatchCard.tsx line 85 is z-30.

Worth a quick pass to correct the three comment blocks to match reality.
Smaller things worth a look

The long-press handler doesn't call e.preventDefault() on the Mapbox contextmenu event — Mapbox's canvas typically has touch-action: none already, which should suppress the native OS long-press menu, but worth confirming on an actual Android/iOS device since a stray native context menu popping up alongside your own navigation would be a jarring double-trigger.
MapControlsPanel's useEffect cleanup calls onFiltersSheetChange(false) / onLayersSheetChange(false) on unmount — good instinct, but since those are just setState calls in the parent (map.tsx), and map.tsx itself is unmounting at the same time in the case that matters (leaving the Map screen), this cleanup is mostly inert for that case and only actually matters if MapControlsPanel alone unmounts while map.tsx stays mounted (e.g. switching to List view or mapError appearing) — which is exactly right, so this is fine, just noting it's a narrower safety net than the comment implies.
