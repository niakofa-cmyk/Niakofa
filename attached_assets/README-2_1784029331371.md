# Niakofa — "Circles disappear on leave/refresh" — actual root cause + fix

## Where these go
- `artifacts/api-server/src/routes/audio-circles.ts` → replaces the existing file
- `artifacts/pay-it-forward/src/pages/audio-circles.tsx` → replaces the existing file

## What was actually happening
Nothing was being deleted. Circles (the permanent "channel" per neighborhood/
city — separate from a live session inside one) were never lost from the
database. Two things combined to make it look that way:

1. **Only Fort Worth ever had circles.** `migration 0064` seeded circles for
   exactly one city, as a one-time data migration. I checked every other
   place in the codebase that touches the `audio_circles` table — there is
   no runtime code anywhere that creates a circle for any other city. Type
   any city other than Fort Worth into the search box (or simply have a
   profile city that isn't Fort Worth) and you get "No circles yet" —
   permanently, not just once, because nothing was ever going to create one.
2. **The city you were viewing wasn't remembered.** The search box's `city`
   state initialized fresh from your profile's default city every time this
   screen mounted — including after leaving a room (which unmounts and
   remounts it) or a plain page refresh. So if you'd searched into Fort
   Worth (the one city with real circles) and then left a room or refreshed,
   the view silently snapped back to your own profile city — which likely
   has zero circles — and you'd see an empty list where a moment ago you saw
   several. That reads exactly like "the Circles are all gone," even though
   the ones you were just looking at are sitting untouched in the database.

## The fix
- **`ensureCirclesForCity` (new, in `audio-circles.ts`)** — idempotently
  provisions a real, permanent circle (city-wide, plus one per known
  neighborhood) the first time anyone looks up a given city, instead of only
  Fort Worth ever having any. Fast path is a single existence check with no
  writes once a city's been provisioned; a genuinely brand-new city gets its
  circles created inside a transaction. (There's a small, explicitly
  commented race window on the very first simultaneous lookups of a brand
  new city — worst case is one duplicate circle row, never data loss — not
  worth more complexity for a first-touch-only path.)
- **Persisted last-browsed city (`audio-circles.tsx`)** — the searched city
  is now saved to `sessionStorage` and restored on remount, so leaving a room
  or refreshing the tab keeps showing you the same city's circles instead of
  silently switching you to a different (possibly empty) one.

## After this
Every city is now self-provisioning the same way Fort Worth was hand-seeded,
and the view can no longer quietly change city out from under you — so
there's no remaining path I could find where Circles appear to vanish from
either a delete or a client-side reset.
