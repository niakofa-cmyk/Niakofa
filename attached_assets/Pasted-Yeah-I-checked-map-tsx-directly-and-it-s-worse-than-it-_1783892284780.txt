Yeah — I checked map.tsx directly, and it's worse than it looks visually. On mobile, at the exact same moment, you can have all of these simultaneously fighting for the same ~375px-wide strip along the bottom:
Bottom-left, one row, four separate pill buttons: Traffic toggle, Heat toggle, Language filter, Category/Urgency filter — positioned at hardcoded left-4, left-24, left-44, left-[188px]. Two of those buttons also pop open dropdown menus that expand upward from that same row, which can overlap each other or the row above depending on button label length (the filter button's text changes from "Filter" to "Filtered" when active, but its box position is a fixed pixel offset, not fluid).
Bottom-right: a 2-button zoom stack (+/–), plus a separate "recenter on me" button that appears/disappears conditionally right above it, plus (in certain states) a "Resume Compass" button at a very specific bottom-[322px] — a magic number almost certainly hand-tuned once to dodge whatever else was on screen at the time, which is exactly the kind of thing that breaks the next time someone adds an element.
Top and center: a banner alert, a live-stats readout, and up to two different centered pill banners ("Search this area" / "Browsing this area") that occupy the identical position depending on state.
Bottom overlay: in Helper Mode, a BottomSheet of nearby requests can be open at the same time as that four-button row sitting right above it.
That's the actual root cause: it's not one crowded toolbar, it's 6+ independently-positioned floating elements, each added at a different point in the project's history (you can see it in the file — each has its own "why this exists" comment), with no shared layout system holding them together. Every new feature added one more absolutely-positioned button rather than fitting into a container.
Here's the redesign I'd make:

Collapse the left-side row into one "Filters" button. Traffic, Heat, Language, and Category/Urgency all become sections inside a single bottom sheet triggered by one button. You go from 4 buttons + 2 popups to 1 button + 1 sheet. Group them logically: "Map layers" (traffic, heat) and "Show me" (category, urgency, language) as two sections in that sheet.
Drop the on-screen zoom buttons. Pinch-to-zoom is native and expected on mobile; dedicated +/- buttons are a desktop-era pattern taking up prime real estate for something users rarely tap. Keep only recenter-on-me, and keep it always at the same corner instead of conditionally appearing/disappearing (a control that pops in and out is more disorienting than one that's just occasionally disabled-looking).
One status slot, not four competing banners. Give the top-center position a single queued-message component: if there's a browsing-away state, a search-this-area prompt, and a "waiting for requests" status, they take turns in one slot instead of three different position rules for basically the same "here's what's going on" message. Same treatment for "Resume Compass" — it's a transient status, it belongs in that same queue, not a bespoke bottom-[322px].
Kill the magic-number positioning. left-44, left-[188px], bottom-[322px] are all pixel values tuned to avoid whatever else happened to be on screen at the time they were written. Replace the whole bottom row with a real flex container (display:flex; gap) so buttons space themselves automatically — that alone prevents the "next feature added breaks the layout" problem your own commit history shows happening repeatedly.
One primary action, one secondary control cluster — this is the Google Maps / Uber pattern: a single FAB-style button for the dominant action (Filters), a small icon-row for secondary toggles (Layers), and everything else lives one tap deep. Right now Niakofa surfaces everything at once instead of surfacing access to everything.

Net effect: the visible mobile map goes from 6+ persistent floating controls down to 3 — Filters, Layers, Recenter — with a single status slot at top and the request bottom-sheet doing its own thing lower down, never overlapping the button row above it.
