Real gaps — in the project's own words, verified against code
The team's own CLAUDE.md is unusually candid, and I spot-checked its claims rather than taking them on faith. These are genuinely open:
1. 63 of ~100 live API routes have no OpenAPI contract entry — including all of /stripe/*, /verification/*, /admin/*, /nia/*. This means big parts of the frontend call these with hand-written fetch and zero compile-time type safety. Not a bug today, but a landmine for future changes (a route can silently change shape and nothing will catch it at build time).
2. No payment-splitting across multiple helpers. request_helpers is coordination-only — one helper gets claimed, paid, and rated per job. If your vision includes group tasks where several helpers split a payout, that's an explicit, real gap requiring a dedicated Stripe Connect design pass, not a quick fix.
3. No voice I/O for Nia yet.
4. Legal review is still outstanding. The ToS/waiver text (liability, "PIF is a gift not a loan," no-warranty) exists and is enforced server-side, but the docs explicitly flag it as not yet reviewed by a Texas attorney — important before scaling regulated categories like childcare, senior care, and medical.
5. Single-county only, hard-coded. Civic resources, ToS text, and Nia's context are all Tarrant County/Fort Worth-specific. Expanding to other counties (your "county open portal" language) is called out as a real, unscheduled multi-session schema/contract project — not a toggle.
6. businesses_enabled feature flag needs a one-time DB setting before the business-request flow is live in any given environment — easy to forget on a fresh deploy.
7. DB migrations not yet applied in dev as of the last session note — relation does not exist warnings are logged (non-fatally) until pnpm --filter db run migrate is run. Worth confirming this is done in whatever environment you're about to demo or launch from.
8. No load/performance testing done yet and no APM (Sentry/Datadog/New Relic) wired — fine at low volume, a real risk once real money and real urgent requests are flowing at scale.
