# Nia health-check fail-open fix

## What this fixes
`artifacts/api-server/src/routes/health.ts` had the `/status` endpoint's
`nia_ai` check reading the kill-switch as `val !== "false"` — meaning a
missing row, a DB error, or any unexpected value was reported as **enabled**.
Every other Nia gate in the codebase (`nia-proxy.ts`, `nia-voice.ts`,
`nia-service/src/lib/db.ts`) is fail-**closed**: only an explicit `"true"`
counts as enabled. This brings the health-check display in line with that.

This is a display-only fix — it does not change whether Nia actually runs,
only whether the `/status` health page accurately reports it.

## How to apply it

**Option A — replace the file directly**
Copy the attached `health.ts` over:
```
artifacts/api-server/src/routes/health.ts
```
in your real working repo (the one whose `git remote -v` matches your
Railway source), then:
```bash
git add artifacts/api-server/src/routes/health.ts
git commit -m "fix: nia_ai health check was fail-open, now fail-closed"
git push
```

**Option B — apply by hand**
Find this block in `artifacts/api-server/src/routes/health.ts`:
```ts
let niaEnabled = false;
try {
  const val = await getSystemSetting("nia_enabled");
  // null means row is missing → treat as enabled (safe default on first boot)
  niaEnabled = dbOk && val !== "false";
} catch { /* fall through */ }
```
Replace with:
```ts
let niaEnabled = false;
try {
  const val = await getSystemSetting("nia_enabled");
  niaEnabled = dbOk && val === "true";
} catch { /* fall through */ }
```

## After pushing
Railway will redeploy automatically on push (if auto-deploy is on for that
branch). Once it's live, `GET /status` on your api-server will correctly show
`nia_ai: false` whenever the kill-switch is off, instead of defaulting to
"on" on a missing/errored row.
