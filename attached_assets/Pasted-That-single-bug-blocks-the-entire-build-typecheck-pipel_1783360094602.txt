Result: there is exactly one real bug, but it's a total build-blocker.
The error

error TS2688: Cannot find type definition file for 'node'.
  The file is in the program because:
    Entry point of type library 'node' specified in compilerOptions
This fires while building lib/trust-tiers, and it kills the entire pipeline immediately — pnpm run build and pnpm run typecheck both exit with code 2 before ever reaching api-server, pay-it-forward, nia-service, or scripts.
Root cause: lib/trust-tiers/tsconfig.json sets "types": ["node"] (same as lib/db), but unlike lib/db, lib/trust-tiers/package.json declares no devDependencies at all — so it never gets its own @types/node package linked into node_modules. Compare:
* lib/db/package.json → "devDependencies": { "@types/node": "catalog:", ... } ✅
* lib/trust-tiers/package.json → no devDependencies key at all ❌
Because pnpm uses strict, per-package node_modules, TypeScript can't resolve @types/node for that package, and the whole tsc --build chain aborts there.
Downstream impact
Since api-server imports from @workspace/trust-tiers (in src/lib/community-pool.ts, src/routes/leaderboard.ts, src/routes/requests.ts), once the libs build fails, api-server's typecheck also fails with cascading TS6305 errors ("Output file ... has not been built from source file ...") — but that's just fallout from the same root cause, not a separate bug.
Verification

"devDependencies": { "@types/node": "catalog:" }
