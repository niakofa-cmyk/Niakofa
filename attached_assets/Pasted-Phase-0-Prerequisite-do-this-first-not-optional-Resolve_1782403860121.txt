Phase 6 — Voice I/O (the big one — separate track, separate timeline)
This is not a weekend addition; it's a real subproject:

STT: add a /api/nia/voice/transcribe endpoint (api-server, proxied to nia-service or a dedicated provider — Whisper API is the standard choice). Frontend: a push-to-talk button in NiaDrawer.tsx using MediaRecorder, sending audio blobs.
TTS: Nia's text responses need a voice — pick a provider (ElevenLabs, OpenAI TTS, or similar), stream audio back alongside/instead of the SSE text stream nia-proxy.ts already pipes.
Latency budget: voice changes the UX contract — a 3-second text-generation delay is invisible in chat, glaring in a voice call. This likely needs streaming TTS (sentence-by-sentence) layered onto the existing SSE pipe in nia-proxy.ts, not a bolt-on after full-response generation.
Cost model: voice (STT+TTS, every turn) is meaningfully more expensive per conversation than text — needs its own rate limiting tier (crisisAwareChatLimiter's sibling), distinct from the existing chat limiter.
