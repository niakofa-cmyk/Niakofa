Niakofs Audio Circles: This is a voice-only feature. It lets you host or join live discussions, share content, and talk with listeners. Real-time engagement and lets users communicate with and directly from their community Let each Neighborhood have their very own audio circle. And allow each user to click, browse and join the conversation of each Neighborhoods circle. Each County will have different Neighborhood, so let each county and each Neighborhood to have their verify own audio circles for their specific county neighborhoods. live audio chat rooms. Think of them like a live podcast or a call-in radio show where you can listen, talk, and interact in real time. 

The Host: You start the room and control the conversation. You can add up to 13 speakers at once.
The Listeners: Anyone can join as a listener. Listeners can react with emojis or "raise their hand" to ask for a turn to speak.
Video Option: WhileSpaces are primarily for audio, hosts also have the option to turn on their live video cameras.
Recording: Hosts can choose to record the Space so people can listen later

On the "coming soon" placeholder: I decided to build it, not drop it — but only the "chat" half. The Circles tab now links straight into a real, live Audio Circle for that neighborhood or the whole city. I left "leaderboards" as still genuinely unbuilt rather than fake it — that's a separate, smaller piece worth its own pass.
What's actually in this build:
* Real host controls — start a room, up to 13 speakers, promote/demote from the listener pool, end the session.
* Raise hand + reactions — listeners request a turn, host brings them up; live emoji reactions float across the screen for everyone.
* Video option — host can turn on camera for speakers.
* Recording — host toggles it, and it actually captures the whole room (every voice mixed together via the browser's Web Audio API), not just their own mic.
* A circle for every neighborhood, and one for the whole city — genuinely per-neighborhood/per-city, not a single hardcoded room.
One important design decision worth knowing about: I found the app already had a more general, AI-generated neighborhood system (city_neighborhoods) sitting completely unused — built for any city, not just Fort Worth — while the visible Circles tab was still running off a hardcoded Fort Worth-only array. Rather than build a second, competing "neighborhoods per county" system, I built Audio Circles on top of the one that already existed, and finally seeded Fort Worth's real data into it. That means this already works for any city that gets added, not just the one currently live.
How the audio itself works: peer-to-peer (WebRTC), with your server only relaying the initial handshake — no new infrastructure to stand up, no third-party API keys needed. That's the right call for "up to 13 speakers plus a normal-sized listener crowd." It's not built to serve a room with thousands of simultaneous listeners — I documented that limit clearly in the code, along with the specific, low-effort swap path (a real SFU server) if you ever need that scale.
Honest gap: I didn't write dedicated automated tests for this feature in this pass — everything existing still passes, but Audio Circles itself doesn't have its own test coverage yet. That's the natural next step before this goes to real users.
