CRITICAL BUGS
BUG-CRIT-01 — nia-service Dockerfile: wrong table name in getActiveRequest()
File: artifacts/nia-service/src/lib/db.ts Line: FROM help_requests WHERE id = $1 The nia-service queries help_requests directly via raw SQL, but the actual Drizzle-managed table is requests (from requestsTable). This causes every getActiveRequest() call to return null, meaning Nia never has live request context during active jobs. Every helper/requester conversation while on a job is context-blind.

BUG-CRIT-02 — nia-service Dockerfile: wrong table name in getCompletedRequestsForCheckin()
File: artifacts/nia-service/src/lib/db.ts Same file — FROM help_requests hr LEFT JOIN users u ON u.id = hr.helper_id. Table is requests not help_requests. The 24-hour check-in worker never fires because this query always returns 0 rows. Nia's follow-up feature is completely broken in production.

BUG-CRIT-03 — reports.ts missing sos in CreateReportBody enum
File: artifacts/api-server/src/routes/reports.ts CreateReportBody enum does NOT include "sos" as a valid type, but verification.ts inserts rows with type: "sos" directly via db.insert(reportsTable). This works at the DB level (the schema allows it) but means the public POST /reports route cannot be used to file an SOS-type report. The two code paths are inconsistent — the safety endpoint bypasses validation while the general reports endpoint blocks the type.

BUG-CRIT-04 — Stripe webhook: transfer.created handler matches by stripe_transfer_id on a row that hasn't been set yet
File: artifacts/api-server/src/routes/stripe.ts In the transfer.created case: db.update(paymentTransactionsTable).set(...).where(eq(paymentTransactionsTable.stripe_transfer_id, transfer.id)). The stripe_transfer_id on the row is only set AFTER the transfer fires — so this WHERE clause matches 0 rows. The update is a no-op, the row stays in authorized state forever. The transfer.created webhook handler silently does nothing.

BUG-CRIT-05 — nia-service: model string "claude-haiku-4-5-20251001" is not a valid Anthropic model ID
File: artifacts/nia-service/src/routes/chat.ts Memory extraction uses model: "claude-haiku-4-5-20251001". The correct model ID is claude-haiku-4-5 or claude-haiku-4-20240307. The malformed ID will throw an Anthropic API error on every memory extraction call. Memory never updates — every user's Nia starts fresh every conversation.

BUG-CRIT-06 — nia-service: model: "claude-sonnet-4-6" is not a valid Anthropic model ID
File: artifacts/nia-service/src/routes/chat.ts streamNiaResponse() uses model: "claude-sonnet-4-6". Correct IDs are claude-sonnet-4-5 or claude-3-5-sonnet-20241022. Invalid model ID means every Nia chat call fails with a 400 from Anthropic. Nia is entirely broken in production.

BUG-CRIT-07 — nia-service is NOT in the pnpm workspace
File: pnpm-workspace.yaml Workspace includes artifacts/* and lib/* — but artifacts/nia-service has its own standalone package.json with no workspace dependencies. However nia-service does NOT import @workspace/db, @workspace/api-zod, etc. It uses its own raw pg pool. This means the nia-service has a completely separate, drift-prone DB schema from the main app. Any schema change in lib/db is invisible to nia-service unless manually duplicated in migrate.sql.

BUG-CRIT-08 — nia-service/src/routes/chat.ts: /checkin route uses wrong INTERNAL_SECRET env var
File: artifacts/nia-service/src/routes/chat.ts The check-in route checks process.env.INTERNAL_SECRET, but community-neighborhoods.ts and region-crisis-resources.ts in the api-server send X-Internal-Secret: SESSION_SECRET. The env var names differ — INTERNAL_SECRET vs SESSION_SECRET. Either the checkin worker will fail auth silently (returning 401) or the region/neighborhood routes will fail. Both paths use the same secret but different env var names across services.

BUG-CRIT-09 — Race condition: POST /requests/:id/complete is not wrapped in a transaction
File: artifacts/api-server/src/routes/requests.ts The completion flow does: UPDATE requests SET status=completed → UPDATE users SET help_count+1 → INSERT transactions → stripe.transfers.create → INSERT paymentTransactions. If any step between the status update and the Stripe transfer fails, the request is marked completed with no payout record and no way to retry via the normal flow. No DB transaction wraps any of this. The enqueuePayoutRetry fallback only triggers if Stripe throws, not if the DB insert fails.

HIGH SEVERITY
BUG-HIGH-01 — push.ts: sendPushToUsers() fetches ALL users to build email map
File: artifacts/api-server/src/routes/push.ts

const users = await db.select({ id: usersTable.id, email: usersTable.email }).from(usersTable);

No WHERE clause. Loads the entire users table into memory to build an email fallback map. Will cause OOM or extreme latency at scale.

BUG-HIGH-02 — admin-analytics.ts: /admin/accounts has no pagination
File: artifacts/api-server/src/routes/admin-analytics.ts GET /admin/accounts does db.select(...).from(usersTable).orderBy(usersTable.created_at) with no LIMIT. Full table scan returned to the browser on every admin page load.

BUG-HIGH-03 — leaderboard.ts: in-process cache keys for city filter are never evicted
File: artifacts/api-server/src/routes/leaderboard.ts Leaderboard uses cacheGet/cacheSet for the main key and city-specific keys. invalidateLeaderboardCache() only deletes "leaderboard:all". City-specific cache keys ("leaderboard:city:*") are never invalidated after a request completes. City leaderboards can show stale data indefinitely.

BUG-HIGH-04 — nia-context.ts: in-process contextCache Map grows unbounded in multi-instance deployments
File: artifacts/api-server/src/routes/nia-context.ts The cache is a module-level Map — not Redis-backed. On Railway with multiple instances, each instance maintains its own isolated cache. The eviction logic only runs when contextCache.size > 1000, which is per-instance. On low-traffic deployments the map never evicts. On high-traffic multi-instance, each instance caches redundantly with no shared invalidation.

BUG-HIGH-05 — recurring.ts: processRecurringRequests() uses dynamic import("drizzle-orm") inside a worker loop
File: artifacts/api-server/src/routes/recurring.ts

const { lte } = await import("drizzle-orm");

Dynamic import inside a hot path is a performance anti-pattern and can cause unexpected module initialization behavior. Should be a static top-level import.

BUG-HIGH-06 — users.ts: PATCH /users/:id uses (updates as any).city etc. for extended fields
File: artifacts/api-server/src/routes/users.ts

if (city !== undefined) (updates as any).city = city;

The comment says "Extended profile fields — validated by UpdateUserBody Zod schema" but the cast to any on the Drizzle update object bypasses TypeScript's column validation. If city, specialties, phone_masked, or quick_replies don't exist as columns in usersTable, Drizzle will silently ignore the update — no error, no feedback to the caller.

BUG-HIGH-07 — nia-proxy.ts: session ID ownership validation is bypassable
File: artifacts/api-server/src/routes/nia-proxy.ts

if (userId !== undefined && !sessionId.startsWith(`${userId}-`) && !sessionId.startsWith(`anon-`))

Any authenticated user can read any other user's history by using a session ID prefixed with anon-. The anon bypass has no further validation.

BUG-HIGH-08 — stripe.ts: POST /stripe/payout (admin) has TOCTOU on payout state
File: artifacts/api-server/src/routes/stripe.ts State check: if (pt.state === "completed") return 409 — then later: await stripe.transfers.create(...) — then UPDATE SET state='completed'. Two concurrent admin calls can both pass the state check and create duplicate Stripe transfers before either updates the row.

BUG-HIGH-09 — sw.js: service worker precaches /offline.html but file doesn't exist in public/
File: artifacts/pay-it-forward/public/sw.js PRECACHE_ASSETS includes /offline.html. There is no offline.html in public/. The install event's cache.addAll(PRECACHE_ASSETS) will throw, causing the service worker install to fail entirely. PWA offline support is broken — no caching, no push notifications.

BUG-HIGH-10 — manifest.json: only SVG icons, no PNG fallback
File: artifacts/pay-it-forward/public/manifest.json Both icons are "src": "/favicon.svg". Android and some iOS/Chrome versions require raster PNG icons (192×192, 512×512) for PWA installation, splash screens, and maskable icons. SVG-only manifests fail "Add to Home Screen" prompts on most Android devices.

MEDIUM SEVERITY
BUG-MED-01 — users.ts: delete cascade is incomplete
File: artifacts/api-server/src/routes/users.ts The delete handler manually deletes from scheduledPaymentsTable, stripeAccountsTable, userSettingsTable — then says "requestsTable and transactionsTable should handle CASCADE DELETE if configured." This is speculative. If FK cascades aren't configured, orphaned requests and transactions remain after user deletion, causing broken references throughout the app.

BUG-MED-02 — requests.ts: GET /requests has unbounded limitParam bypass
File: artifacts/api-server/src/routes/requests.ts

const limitParam = req.query.limit ? parseInt(req.query.limit as string) : 200;

Default is 200, max is capped at 500 — but parseInt with no radix can behave unexpectedly on strings like "0x1000" (parses as 4096). Use parseInt(val, 10).

BUG-MED-03 — nia-service: no input length validation on message at the nia-service layer
File: artifacts/nia-service/src/routes/chat.ts The api-server proxy caps messages at 2000 chars, but the nia-service /chat route does no such validation. Direct calls to nia-service (internal or misconfigured) can send arbitrarily long messages directly to Anthropic, causing token overuse and unexpected costs.

BUG-MED-04 — nia-service/src/routes/chat.ts: /analyze-image route has hardcoded "Fort Worth, TX" in system prompt
File: artifacts/nia-service/src/routes/chat.ts

"You are Nia, the Niakofa community assistant for Fort Worth, TX."

The main Nia system prompt (nia.ts) correctly avoids hardcoding a region. The image analysis endpoint hardcodes Fort Worth. Niakofa is a global platform — this breaks the deployment model for any non-Fort Worth city.

BUG-MED-05 — recurring.ts: computeNextFireAt() — weekly recurrence without day_of_week fires after 7 days from NOW, ignoring scheduled time_of_day
File: artifacts/api-server/src/routes/recurring.ts When recurrence="weekly" and dayOfWeek is null, the function advances 7 days from "now" if next <= from. But the initial next is set to today at time_of_day. If time_of_day is in the past today, it adds 7 days — which gives the correct next occurrence. However, on a server restart or re-fire, the new from date is the current time, not the original schedule anchor. Recurring jobs drift over time.

BUG-MED-06 — push.ts: VAPID mailto hardcoded
File: artifacts/api-server/src/routes/push.ts

webpush.setVapidDetails("mailto:hello@payitforward.community",...)

Email is a Niakofa placeholder that doesn't match the actual domain (niakofa.com). Web Push spec requires this to be a valid contact address. Some push providers validate this.

BUG-MED-07 — nia-service/src/lib/db.ts: getRecentHistory() hardcoded limit=12 ignores caller param default
File: artifacts/nia-service/src/lib/db.ts getRecentHistory(sessionId, limit=12) — the parameter exists but is always called without a limit argument from chat.ts. 12 turns of history (6 exchanges) is very shallow for a community crisis-support AI. Should be at least 20.
