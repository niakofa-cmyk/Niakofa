The ZIP was useful — but we should use it correctly

I inspected the supplied Compose-Snapchat-Clone-master.zip.

It is an Android Jetpack Compose Snapchat-style UI clone, not a production media engine.

Its useful donor patterns are:

full-screen camera
circular shutter
front/back camera switching
flash/torch
dark immersive camera canvas
vertical Spotlight playback
creator/action overlay
Stories presentation
Memories concept
simple camera-first navigation
cyan/blue/yellow/purple/red creative accents

For example, its ThemeColors explicitly uses cyan as a primary creative color:

BLUE   #00CCFF
YELLOW #FFFF00
PURPLE #9D00FF
RED    #FF0051

and its camera is intentionally built around a full-screen PreviewView + large circular shutter + camera controls.

Its Spotlight experience is also deliberately full-viewport video-first, rather than a dashboard.

Those are exactly the patterns worth bringing into Niakofa.

But I would not copy the ZIP's architecture or mock data.

Niakofa's current media infrastructure is considerably more sophisticated.

The >60-second Family Story idea is good — with one important architectural distinction

I would implement:

Spark/Moment

Short-form Community content.

When composed media exceeds 60 seconds

The Studio recognizes:

Family Story Candidate

and displays:

This Spark can become a Family Story.
Your creation is longer than the 60-second Moment limit. Save a private Family Story copy.

Then:

Keep as Moment only

or

Save as Family Story

The important thing is that this should be an explicit preservation decision.

The current Family Vault architecture already has actual family media assets:

family_memory_assets

including:

photo
video
audio
document
storage key
thumbnail
duration
processing state

So the backend has a foundation for true media preservation.

But the current KeepForMyFamilyDialog explicitly says it saves caption text only.

That means we should not pretend the existing keepMoment() API archives the video.

The proper future flow is:

Spark > 60 sec
       ↓
Family Story Candidate
       ↓
User confirms
       ↓
Create Family Memory
       ↓
Upload/copy media into Family Memory Asset
       ↓
Process video
       ↓
Family Story references Memory
       ↓
Private Family preservation

That preserves the existing Community/Family lifecycle boundaries instead of silently extending the Moment's retention.
